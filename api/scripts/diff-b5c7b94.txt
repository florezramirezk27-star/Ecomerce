    fix(dropi): el stock local sigue al de Dropi y deja de bloquear ventas validas
    
    El stock de la tienda ahora es el de Dropi, en ambos sentidos, y se acabaron los 'stock insuficiente' falsos:
    
    - computeStock: un producto VARIABLE con variations:[] devolvia 0 y nunca caia a warehouse_product, dejaba el stock local en 0 y rechazaba la venta. Ahora exige variations.length > 0 (igual que el frontend).
    
    - validateStock: si Dropi no responde o no encuentra el producto no se bloquea la compra (se registra y se sigue); solo corta cuando Dropi confirma available < solicitado.
    
    - syncStock: solo escribe/cuenta los productos cuyo stock cambio (nuevo contador 'unchanged'); el aviso de precio minimo se revisa siempre.
    
    - checkout: re-sincroniza el stock de los productos de proveedor justo antes de validar y descontar, para no vender con stock viejo; invalida la cache de catalogo tras el checkout y al cambiar de estado.
    
    - panel admin: el mensaje de sincronizacion incluye los 'sin cambios'.
